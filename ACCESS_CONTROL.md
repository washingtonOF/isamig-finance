# Authentication and access control

Use Google OpenID Connect with verified email, issuer, audience, expiry, nonce and state validation on the backend. Bootstrap master email from server-only MASTER_EMAIL configuration, never a public repository constant. Bind master to verified Google subject after secure initial provisioning. Deny unapproved users by default. Store roles and active status server-side; check on every protected request, including reports and BI endpoints. Master can approve/revoke users and assign finance or read-only roles. Revocation invalidates active sessions. Use secure HttpOnly SameSite cookies, CSRF protection, HTTPS, audit records and rate limits. Never collect Google passwords. Keep existing demo isolated from real data until authentication is implemented and tested. Google OAuth client configuration and private deployment are required.
